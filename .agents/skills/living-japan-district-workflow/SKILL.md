## 工作方式

中央统一口径，区负责人切片并归挂：先建立本区可用小片框架，再让小批按同版框架分拣，按大体位置及写作关联就近吸纳；过程中补充、合并片区线索。就近是写作小片组织，不要求逐点官方精确归属。

目标是速度、准确业态分类和可用于写作展开的地点子集。优先收纳、逐层归挂，主动减少同级直接堆点。可用小片建立后就近吸纳，同一个源点保持唯一，不因多个小片复制点位；已有设施内部链继续复用。点位已有余量，不为保住每个可疑点投入考证。

区负责人可集中取得现成官方或可靠非官方划分，利用现有地址和大体位置形成可用框架，记录采用方式。不逐点追查精确片区边界，不以新定位、精确多边形、全量社群研究或性质词条齐全为前置。普通点位小批继续执行下面的止查规则。

- 每个子 Agent 默认每批 50 个对象。
- 复杂对象由区 AI 自行缩小批量，不设固定对象数门槛。
- 每批保存结果、证据引用和待判项后，自动领取下一批。
- 在已授权整区范围内连续处理，不逐批等待人工确认。
- 完整店名一眼能大致判业态，就接受大致相容的原类或合理宽类，不为更细分类追查；店名与地址能判归属就直接归挂。
- 普通点位只有无法判断大致业态才搜索，每个未知对象只搜一次，可将本批未知对象集中检索；细则见总规则第 2、3 节。先用现有资料和本区框架判断，公共信息不足、公众用途不明直接排除，其它名称、身份、位置或归属冲突才待判；片区新线索交区负责人合并，不各自造框架。
- 本工程服务写作尺度。公共信息不足、无法辨认公众用途的点直接按下述规则排除；其它身份、位置或疑似同体问题才标黄／红止查，不要求查清现实同体才结束本批。
- 脚本生成全区底表、自动预分类、复制原行都不算人工处理完成。
- 不逐批重写大报告。主档任务记录与辅助待判记录承接进度。

正式范围是本区全部 Overture 输入。小批是处理节奏，不是抽样；正常点也必须处理。

### 公共信息不足：直接排除，不退回再判（2026-11-01 用户确认）

**利用现有资料仍缺乏可用公共信息、无法辨认面向公众用途的点，按本工程逻辑视为写作重要性低，或倾向保密／内部使用，直接按非公共开放设施作 `exclude`。**无需取得“不对外开放”的明确证明，不先标黄等待重判，不为确认开放性追加搜索；只有业态未知才按既定规则搜索一次。

保留原ID、原行和“公共信息不足，按非公共开放设施逻辑排除”的简短理由后继续下一项。中央接受这种工程判断，**不得仅因缺少内部专用的确证而打回重判、补证或重新标黄**。这是写作筛选判断，无需追加现实准入认证。

完整名称或现有资料已经能辨明餐饮、零售、就医、办事、普通预约等公众用途时，照常保留；缺官网、缺详情或个别字段缺失不单独触发本条。身份、位置及疑似同体冲突仍按各自规则处理。本次规范更新不自动重开已审收区或清理旧待判库。

50 个是起点，不是已经验证的最佳值。每个区聊天只专注一区，中央读批次摘要；区负责人有限核对结果。出现无关词片机械套类、漏项或混淆关系时缩小复杂批次，不把正常辨名归类误当机械套类，也不因此改成逐店查证或新增固定轮次审核。

## 文件分工

| 文件 | 用途 |
|---|---|
| 每区 `行政区主档.md` | 唯一持续维护的主档。保存元信息、有效对象、已接受关系和任务。 |
| 每区 `辅助记录.md` | 保存其它唯一去向、来源证据、待判及覆盖；不重复主档有效对象。 |
| 原始 Overture、机器底表 | 只读输入及原行追溯，不直接改原值。 |
| 自动十表、索引、统计 | 从主档生成；不手工维护为另一份正本。 |

主档合同：[每区唯一 Markdown 主档合同](../../../工程表/行政区重建/流程/唯一主档合同.md)。

正式工作目录为 `工程表/行政区重建/整区/档案/{行政区代码}/工作/`。其中 `.baseline/` 只读；中央回货内 `authoring/` 是受审快照，不另行维护。

程序入口为 `scripts/overture/district_archive.py`。`init` 初始化，`build` 派生，`check` 检查；`claim-batch` 领取互不重叠的批次，保存实际覆盖后 `finish-batch`，再自动续批。程序不替区 AI 作判断。

## 按角色读取

| 角色 | 再读 |
|---|---|
| 主任务／中央审收 | `流程/主任务流程.md`、`流程/回货合同.md`、调度实际状态 |
| 区负责人 | `流程/区任务说明.md`、`流程/字段参考.md`、正式区输入与检查点 |
| 更新／接力 | `流程/更新与续接.md`、主档任务记录与现有回货 |

表中 `流程/` 均指 `工程表/行政区重建/流程/`。

中央 6astra 负责共同规则、共用参考入口、跨区 owner、动态派区和有限统一收货，不逐片审批。每个独立区聊天由 6.1sol 负责本区片区框架、实际切片归挂及跨批合并，可用 3 个子 Agent 并行分拣小批。

同区子 Agent 通过批次领取避免对象重叠，收到共同片区框架与本批资料后归挂、反馈新线索，由区负责人合并本区两份 Markdown。区负责人用 `area_partition` 任务及实际对象范围维护框架工作；源对象处置覆盖与片区建立／归挂／跨批合并分别报告，详见区任务说明。各区结果由同一中央主审接收；跨区主体只有一个 owner。

## 必须保留的口径

- 唯一地点源是 Overture `2026-10-21.0`。旧点库、T1、旧铁路与美食名录不作为新点输入。
- 官方或可靠非官方地理划分可支撑结构片区；行政、地址、建筑和用途资料辅助判断，不另补外部店铺或设施点库。旧精选名字与正文仅留后期线索。
- 分类用 `共用/classification-contract-index.json` 的 `activeTreeCategories`；资料标签另存。按总规则第 3 节的大致业态尺度判断，自动分类可改，不以“还能更细”为返工理由。
- 普通有效对象不选代表；可疑冗余按写作尺度取舍。全部保留对象按真实层级归纳，只记直接父；祖先子集沿成员图汇总。
- 生态街区和小片服务写作与程序展开，不等于行政区、站点或性质标签。利用已有划分形成框架后，按大体位置及写作关联就近吸纳，不因精确边界未证实而搁置合理归挂。
- 生态街区下可有更小片区、某街／某站／具名地点周边、商业街和综合设施；积极逐层收纳，减少同级平铺。同一个源点保持唯一，不因多个小片复制点位。性质词条有据顺便挂，不因标签不同就自动拆区。
- 已有商业街、综合设施、店铺及小设施内部链继续复用；外围点进入就近周边小片，不塞进本体内部。写作小片组织与精确物理容纳分别说明，车站周边不等于车站内部。
- 生态街区与下层小片区自然使用一带、周边、附近、圈等合理工程名称，避免过多地名堆叠，不硬性限制地名个数，不为命名另查或返工合理结果。“高层建筑群”等学术性、外观型概括不作新片区名，外观只挂性质词条；用途／生态名须有依据。
- 结构片区允许 `categoryId` 暂空，有值则须有效；名称与位置记录说明大体位置及采用方式，不要求逐点官方精确归属。原位置、地址和现成划分够用时直接归挂，不要求新增定位、精确多边形、固定片区数、全标签或零待判。
- 源对象实际作父时填写父类型，普通叶子无需。用途分类不代替容纳结构。
- 先按公众用途和点位粒度筛选，再归挂。公共设施的纯编号门、出入口、跑道及纯运行点继续排除留痕。后续设备／吸烟点排除、本次点名既有设备例外及其它既有设备不回溯的范围，统一见总规则第 4 节。
- 按对象本体判断，不按“门／入口”等名称关键词硬删。正常旅客准入不等于员工内部。
- 位置修正保留原值、采用值和依据。排除、归并、旧关系和历史写法保留去向。
- 分店、分寺的工程识别名必须完整到“品牌＋○○分店”“寺名＋○○分寺”或有依据的具体寺名，不能只有品牌或裸地名。已有完整店名、院名优先保留。
- 原始名只读；派生工程识别名注明依据。异名、片假名、异体字和来源已有拉丁写法只记录，不自动成为运行显示名或激活词。
- 黄／红对象、停止原因和疑似对应 ID 写辅助记录。红色表示倾向弃置，不冒充已证实不存在或同体；详细口径见总规则第 4、8 节。
- 正文、一句话、搜索优化和后期公共项目下潜不在当前分拣中提前完成。

分类与标签入口均在 `工程表/行政区重建/共用/`。完整筛选细则见总规则，不另加白名单、代表配额或五源六审。

## 派工与完成边界

完整离线总包及正式区输入未就绪，不派区施工。

用户已授权按流程开聊天后，才调用实际 `create_thread`。计划中央角色为 `gpt-6-astra`，独立区聊天为 `gpt-6.1-sol`。推理强度由中央决定。

首批按用户 2026-11-01 最新授权处理首都圈源点位较少的 3 个区：埼玉市西区（11101）、樱区（11106）、横滨市荣区（14115）。以固定本地源全量统计为据，不沿用大田／中原先行安排。本轮只派这 3 区；后续仍按用户授权与真实容量安排，不混算独立聊天与子 Agent 槽位。

模型、强度和真实 threadId／hostId 以实际工具调用记录为准。不自称已切换中央模型，不伪造派发。

只读规划不建聊。主任务从文件自动收货，区聊天无需自行对外发消息。自动收货形成候选成果；最终由用户与中央 6astra 共同判断后才启用，不自动写入运行库。

文件检查、隔离验证、真实聊天、浏览器和 SillyTavern 分别报告。测试界面只用内置浏览器。GitHub 上传另经确认；不上传离线大包、缓存、本机路径或运行个人文件。
