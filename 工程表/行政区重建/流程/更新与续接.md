# 更新与续接

## 先找到真实检查点

主任务换聊天先读仓库 Skill、共同规则版本、主档任务、实际队列与现有回货。

优先续原任务或审已有回货，不重复开区。旧点库与 v1 先导不是可恢复的新地点进度。

区负责人中断后从最近已保存批次继续，同时读取 area_partition 任务、本区片区框架所据主档版本及未合并线索。自动底表存在不表示该批已判断，源覆盖完整不表示片区任务完成。

## 小批保存

每个子 Agent 默认每批 50 个对象，复杂批次由区 AI 自行缩小。

每批保存：

- 本批任务及实际对象范围。
- 主档中的采用判断和必要字段。
- 本区片区框架变化、新线索及跨批合并的实际进度。
- 辅助记录中的证据、待判及处置结果。
- 实际检查点和下一动作。

保存后自动领下一批，不一次领取成百上千对象，也不逐批等人确认。任务未做完就记录真实进度，不能填完成。

不逐批重写整区报告。只有领取、保存、回货、审收或重开等实际事件才更新管理信息。

## 多人交接

每个独立区聊天由 6.1sol 负责整区切片与归挂，可用 3 个子 Agent 并行小批。区负责人集中核对划分依据、维护共同框架并统一合并结果，批次领取避免对象重叠。换子 Agent 时提供同版框架，不让各批另立片区体系。

中央 6astra 统一口径、共用参考和跨区 owner，按实际容量动态派发区聊天并决定推理强度，不固定并发，也不混算聊天和子 Agent 槽位。换负责人时保留领取版本和检查点。

各区必须使用同一份共享 Skill、总规则、字段合同及分类版本。最终由同一中央主审统一收货。自动收货形成候选，用户与中央共同判断后才启用，不自动写入运行库。

回货基于领取版本。出现更晚已收结果时，按对象 ID 合并本批变化，不用旧整份主档覆盖当前档。

共享路径相对仓库根。本机离线资料目录重新配置后继续，不复制一套规则到新机器。

## 事实更新

位置修正保留原值、采用值、原因与依据。名称变化不另造主体，旧写法保留来源和历史角色。

只记直接父，不为上层重复挂祖先。直接父或父类型改变后，派生旧自动边退休留痕。

包含关系与 related 分开。相关边只表示实际非包含关联，不代替父子关系。

续接时复用已有小片和合理结果，按大体位置及写作关联就近吸纳仍直接平铺的点；同一个源点保持唯一，不因多个小片复制点位。自然使用一带、周边、附近、圈等名称，避免过多地名堆叠，不因旧的精确范围或严格命名要求重查返工。已有商业街、设施和店铺内部链保留，外围进入就近小片；具体未解决项继续留待判。

子集更新不改变筛选资格。公共设施纯编号门、出入口、跑道等继续排除留痕，不为补树恢复。

## 规则或来源变化

现阶段固定 Overture `2026-10-21.0`。将来换版本须用户另行明确。

只承接本 Overture 工程自身历史，不拿旧地图、T1、旧铁路或美食名录作 base。

新增、变更、缺席分别记录。来源缺席不等于自动删除，也不混入当期输入分母。

规则由中央统一更新。未受影响的已审结果可复用；只重开受影响对象或任务，不因全局指纹变化全区重做。

原冻结区包和已收回货保留原版本。新一轮续接由中央说明共同规则变化、主档版本衔接与受影响范围，生成新派发说明；区负责人不自行改指纹绕过检查。新增片区步骤不撤销已完成的源对象分拣，未受影响的分类和实际父子关系继续复用。

重新派生 JSON、索引和统计，不反向手改派生结果。

## 后期工作

旧精选名字、内容定位和公共项目下潜以稳定任务 ID 继续。

来源材料可放辅助记录，采用结论回到主档。异名仍只收集，不设已采用或激活资格。

正文、一句话、名称统一及地区／资料搜索在相应后期任务中处理，不混入当前分拣完成标准。

## 收口

分别报告源对象处置覆盖与片区框架／归挂任务结果，明确跨批线索合并情况及剩余项。一句话与正文仍是后期空位，不为本轮收口补写。

保留原件、旧主档版本和原回货。恢复前先保存后续变化，不强制重置或清理。

文件、隔离、真实聊天、浏览器及 SillyTavern 分别报告。GitHub 上传按另行确认的范围执行。
