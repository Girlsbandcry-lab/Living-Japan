# 主任务｜派工与单一审收

## 1. 先核当前状态

读仓库 Skill、总规则、现有领取记录、主档任务及检查点。

优先接已有回货和原任务。旧点库或 v1 先导不算可续的新地点进度。

完整离线总包及正式区包未就绪时等待，不让区 AI 临时反复抓源。

正式输入核来源版本、真实分母、全部 records 分段和冻结指纹。疑点索引不能代替全集。

## 2. 固定共同版本

派工时给出：

- 行政区代码、唯一 owner 与任务 ID。
- 正式源包、主档工作目录、辅助记录入口。
- 领取的主档版本。
- 共享 Skill、总规则、字段合同和分类合同版本。
- 本地参考资料、已有检查点及回货位置。
- 共用片区依据入口、本区已有片区框架与本轮 `area_partition` 任务范围。

共享路径相对仓库根；本机离线资料位置由实际环境解析，不写死盘符。

同一批区使用同版规则。中央改规则后明确受影响项，不能让各区自行换版本。

## 3. 多区与小批

首批按 2026-11-01 最新授权派埼玉市西区（11101）、樱区（11106）、横滨市荣区（14115）三个较小行政区，各覆盖全部本源输入。旧大田／中原先行安排已被替代，本轮不派第四区。

中央 6astra 统一划分口径、共用参考与词条，协调跨区 owner，并按真实 GPT 容量动态派发 2—3 个或更多独立区聊天。每区由 6.1sol 负责整区切片与归挂，可用 3 个子 Agent 并行小批；中央不逐片审批，也不先替所有区完成切片。

区聊天和子 Agent 槽位分别计算。推理强度由中央按任务决定。

区负责人利用现成划分、地址及现有地理资料建立可用小片框架；按总规则第 5、6 节按大体位置和写作关联就近收纳，复用设施内部链，主动减少同级直接堆点。同一个源点保持唯一，不要求逐点官方精确归属、全属性齐全或精确多边形。

每个子 Agent 按以下节奏工作，区负责人统筹合并：

1. 默认取 50 个对象；复杂批次由区 AI 自行缩小。
2. 判断用途、打标签，按区负责人提供的同版片区框架和实际直接父归挂。
3. 保存本批结果、证据引用、待判项及新片区线索，交负责人统一合并。
4. 自动领取下一批，直到本区全部输入都有明确去向。

不得一次要求成百上千对象全部判断。全区底表可以由脚本生成，但不计作处理完成。

中央读任务摘要与真实异常，不把几千行逐项装进主任务上下文。每个区聊天专注一区，区负责人有限核对小批；发现按词猜类、漏项或混关系时缩小复杂批次。50 个只是起点，不新增固定审核轮数或样本数。

批次领取避免子 Agent 处理同一对象。区负责人把返回结果合入本区两份 Markdown，不让并行子 Agent 覆盖整份主档。

源对象批次结束后，区负责人核对跨批片区线索、父子归属和框架任务结果。源对象已有去向不自动表示片区工作已完成。

已授权整区内不逐批等人确认。多个区并行，中央由同一位主审统一收货。

## 4. 实际聊天工具

已获用户开聊授权后才建真实聊天；只读规划不建聊。

| 工具／记录 | 要求 |
|---|---|
| list_projects | 核真实项目 ID 与路径。 |
| 中央角色 | 计划 gpt-6-astra；实际模型以工具状态为准。 |
| create_thread | 独立区聊天指定 gpt-6.1-sol。 |
| 推理强度 | 中央按任务与容量决定，不固定一档。 |
| threadId／hostId | 取得真实值后登记；clientThreadId 不是已创建。 |
| wait_threads | 用游标读紧凑状态，避免重复抄进度。 |
| 接力／返修 | 复用已有授权和原聊天，不重复开同一区。 |

主任务从文件自动收货，区负责人无需自行对外发消息。模型、强度与派发必须有实际工具记录；不自称已切换模型。Skill 不擅自创建新的后台自动唤醒。

## 5. 主档与回货

`district_archive.py init` 初始化主档。已有主档则继续，不覆盖重建。

区负责人编辑主档与辅助记录。JSON 十表由 `build` 派生，不要求人再填另一套表。

回货必须指明领取版本及本批任务。中央按对象 ID 合并，不能用旧整份主档覆盖较新结果。

队列只管理实际领取、聊天和检查点。地点判断与下潜任务结论以主档为准。

## 6. 一次有限审收

先用 `check` 核字段、来源覆盖、对象 ID、分类、父链和版本，再由固定主审核例外与关键父对象。

- 按总规则第 2、3 节接受大致相容的原类或合理宽类，不因“还能更细”退回，不逐普通点重复外查。
- 不另挑代表成员。
- 不重复正文五源六审。
- 不因空正文退回当前分拣。
- 对公共信息不足、无法辨认公众用途而按非公共开放设施逻辑排除的对象，接受总规则第4节的写作尺度判断；不得仅因没有内部专用确证而打回重判、补证或改黄。

先核公众用途和点位粒度，再核保留对象的全量子集。纯编号门、出入口、跑道等不为补树恢复。

上层子集沿成员图查看全部后代，不能只按直接孩子数判断漏点。具体未解决对象或冲突保留待判，不因写作小片的精确边界未证实退回归挂。

同时核区负责人片区任务：框架是否可用于写作展开、小批是否共用框架、跨批线索是否合并、同级直接堆点是否已积极收纳、同一源点是否重复创建，以及既有内部链是否保留。外围按小片就近组织，无需逐点边界证明；名称自然可辨且不过多堆名即可，不为名称另查或返工合理结果。用途词条暂空不否定结构片区，不设固定片区数、标签齐全或零待判门槛。

退回只点名未闭问题，保留本批已完成部分。先保存主档任务，再生成受审回货并接收。接收后只登记实际回执和调度，不就地改受审快照。自动收货形成候选；最终由用户与中央 6astra 共同判断后启用，不自动写入运行库。

## 7. 报告

每批只更新主档任务、待判与必要检查点，不重写大报告。

阶段结束分别说明源对象处置覆盖，以及片区框架建立、归挂、跨批合并和明确剩余项；再列在跑任务和下一动作。文件、隔离、真实聊天、浏览器及 SillyTavern 证据分开报告。
