# Markdown 主档回货与单一审收

## 回货来源

正式回货只从本区 `行政区主档.md` 和 `辅助记录.md` 生成。

源包保持 Overture `2026-10-21.0`、`pointSourcePolicy=overture_only`。旧点库、v1 先导和混合包不能作为基线。

人只维护 Markdown 主档和辅助材料。十表是自动派生结果，不再单独手填分类 JSON 或关系 JSON。

## 本批必须带什么

| 项目 | 责任 |
|---|---|
| 领取版本 | 对应本批开始时的已知主档和中央版本。 |
| 共同版本 | 来源、Skill、规则、字段合同及分类合同一致。 |
| 本批任务 | 稳定任务 ID、实际对象范围、负责人和真实结果。 |
| 片区框架任务 | `area_partition` 任务、共同框架所据主档版本、大体位置及就近组织方式、跨批合并结果和剩余项。 |
| 主档 | 有效对象、地点字段、直接父成员边、实际关系和任务。 |
| 辅助记录 | 排除／归并／待判等其它唯一去向、证据、名称及实际覆盖。 |
| 派生与检查 | 用同版程序生成；保留实际结果，不手改通过状态。 |

每个子 Agent 默认每批 50 个对象，复杂批次由区 AI 自行缩小。区负责人合并保存后自动续批，不逐批等人确认，也不把全区底表当已完成成品。

完整店名一眼能大致判业态、店名和地址能判归属的，采用已有源字段即可；大致相容的原类或合理宽类按总规则第 3 节接受，不因“还能更细”退货。未知业态只按第 2 节搜索一次，不要求逐店网页或追加检索证据。区负责人另按总规则集中核对可复用地理划分依据，作为片区框架证据。

源分母来自正式输入和原分段指纹。输入不明时如实标明，不用 0 冒充已完成。

## 源记录和事实

全部输入最终都有保留、归并、排除或待判去向。正常点不能漏回。有效对象在主档，其它唯一去向在辅助处置表；同一 ID 不重复保存。

- 保留点有用途分类和明确归属结果。
- 归并有真实目标及身份依据。
- 排除保留原行、原因和依据；写作尺度弃置可引用已有疑点及取舍判断，不要求证明现实不存在。
- 公共信息不足、无法辨认公众用途的点，按非公共开放设施逻辑直接排除并留短理由；中央不以缺少内部专用确证为由打回重判、补证或重新标黄，详见总规则第4节。
- 待判有明确对象、问题和下一动作。
- 位置修正保留原值、采用值和证据。

源对象未知分类、结构片区暂未挂性质词条和空正文是不同问题。结构片区可以暂空用途分类，有值时须为有效 ID；名称与地理记录说明大体位置和就近组织方式，不要求逐点官方精确归属。正文和一句话均为后期空位，不阻塞当前工作。

黄／红是有效的本批处置结果：对象先记 pending_review，问题保持 open，并说明停止原因和后续取舍。附近已有疑似同对象时优先考虑冗余弃置，不为交货穷找同体证明。

有黄／红待判的回货按带待判候选接收，不报为全部事实已确认。已确定不同的分店和真实父子对象不能因距离近被误作重复。

## 层级检查

只记直接父，上层全部子集沿成员图查看。

商场、具体街道、机场、景点和其它实际容纳者同类同理。源父明确父类型，叶子无需增加字段。

生态街区下使用可用小片按大体位置及写作关联就近收纳，减少同级直接堆放；同一个源点保持唯一，不因多个小片复制点位。已有商业街、设施和店铺内部链继续复用，外围进入就近周边小片，写作组织与精确物理容纳分别说明。自然使用一带、周边、附近、圈等名称，不过多堆名即可，不要求官方专名或逐点边界证明，不设数量配额。

包含无循环，跨区只有一个 owner。同一源主体不另造同体结构父。

不挑代表，不重复祖先边或 related。related 只保留实际非包含关联。

先核筛选资格再核子集。公共设施纯编号门、出入口、跑道等不为补树改成保留；名称关键词不作为硬删依据。

## 名称检查

全区名称扫描与原写法有记录。品牌、分店、时期角色及来源可追溯。

工程名须完整辨认具体分店、分寺；不能只有品牌或裸地名。自行组成的工程名注明依据，来源原写法仍完整保留。

收集、工程命名与运行采用分别记录。工程名不自动成为显示名或激活词；自动扫描完成不等于分支或重复疑点已解决。

## 中央接收顺序

1. 核本批领取版本及共同规则版本。
2. 用 `district_archive.py check` 核主档结构与覆盖。
3. 中央 6astra 分别核源对象处置覆盖和区负责人片区任务，有限核异常、点位唯一及已有内部链的承接。
4. 只退点名问题，保留已完成部分。
5. 用同版 `build` 生成派生结果，接收主档原文及其派生快照。受审 authoring 副本不另行维护。
6. 登记实际接收回执和调度索引。主档任务须在生成受审回货前保存；接收后再改主档，必须重新生成和审收。

旧整份回货不能覆盖中央较新结果。按对象 ID 合并已确认变化，并保留原回货和历史版本。

通过结构检查不表示事实全部确定。有明确待判的接收与本轮无未解项必须分开报告。

片区任务说明可用框架、就近归挂方式、跨批合并结果及具体剩余项；不要求固定片区数、全部词条齐备或零待判，不以精确片区归属未证实退回合理收纳。源记录全有去向不能单独证明小片已经有效组织。

## 原文与证据等级

回货保存生成时的两份 Markdown 原文，并校验其指纹。主档变化后重新生成，不沿用过时派生结果。

JSON 快照可以重复生成，不具有独立于主档的人工事实权威。

主档审收、隔离验证、真实聊天、浏览器和 SillyTavern 分别说明。自动接收只形成候选；用户与中央 6astra 共同判断后才启用。接收不等于运行库切换、正文完成或公网发布。
