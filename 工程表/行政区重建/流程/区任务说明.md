# 区负责人｜切片、归挂与小批分拣

## 开始前

读共享 Skill、总规则、唯一主档合同、字段参考及本次派发单。

确认行政区、owner、任务 ID、来源包、主档目录、领取版本和共同规则版本。

独立区聊天由 6.1sol 负责整区，可用 3 个子 Agent 并行处理不同小批。推理强度由中央决定。

只改本区工作稿及辅助记录。不改中央受审快照、其它区、全局规则或分类编号。

正式输入是本区全部 Overture records。旧点库和 v1 先导不是输入；疑点索引也不是全集。

## 先建立本区片区框架

按总规则第 5、6 节利用现成官方或可信地方划分、名称、地址和现有地理资料建立可用框架，再按大体位置及写作关联就近吸纳。这里的“就近”服务写作小片和程序展开，不要求逐点官方精确归属。区级查参考不受逐店“仅未知业态才搜索”的限制，但不为逐点边界另开调查，也不另补外部店铺等来源点。

行政区下采用可用生态街区与小片框架，结合“○○一条街”“某街周边”“某站周边”、商业街、综合设施等逐层收纳，减少同级直接堆点。小片建立后就近吸纳，不按固定点数切块；同一个源点保持唯一，不因多个小片复制点位。性质有现成依据就挂相应词条，暂不明确可留空，不为主题标签单独造地理父级。

新片区自然使用可辨地点、业态或生态名称，可写一带、周边、附近、圈或“××至○○周边”，避免过多地名堆叠即可，不硬性限制地名个数，不为命名另查或返工合理结果。办公区、工业区等用途／生态名须有依据；不新造“高层建筑群”等纯外观或学术性片区名，建筑形态挂性质词条。本条不改真实街道、商业街、桥梁或其它设施本体的合法名称，详见总规则第 5 节。

先建立能用于归挂的部分，再随批次完善；不等待精确多边形、全部属性或全区零待判。区负责人维护主档中的结构对象、关系及 `area_partition` 任务；任务关联实际片区、候选片区或相关源对象，结果引用主档与辅助证据。

## 每批做什么

每个子 Agent 默认每批 50 个对象，复杂批次由区 AI 自行缩小。

1. 逐对象确认保留、归并、排除或待判。
2. 按大致业态选择相容分类或合理宽类；已有明确细类可直接保留，不为更细分类追查。必要时记录兼用和资料标签。
3. 按共同片区框架就近归挂并说明采用方式，复用已有设施内部链；同一个源点不重复创建。
4. 保存异名和原写法证据。
5. 把采用结果写主档，把来源与待判写辅助记录。
6. 新片区或范围冲突交回负责人；负责人合并本批结果与框架变化，保存后自动领取下一批。

批次领取避免重复对象；子 Agent 返回对象级变化，区负责人统一合并，不能互相覆盖整份主档。

区负责人给子 Agent 附同版片区框架、相关范围依据、本批必要原名与地址、已有坐标及同区相关疑似对象。子 Agent 不另起冲突框架。跨批新片区、归属冲突和疑似重复由负责人汇总，不要求子 Agent 通读全区，也不因批次不同漏掉关系。

在已授权整区范围内自动连续处理，不逐批等待人工确认。脚本底表、自动预分类与复制原行不算已处理。小批是工作节奏，正常点最终也要全量处理。

## 分类与位置

使用中央同版 `classification-contract-index.json`。

用途树用 `activeTreeCategories`，资料标签用 `materialTagCategories`。自动预分类可改；分类尺度以总规则第 3 节为准。

以速度、准确业态和地点子集为目的。完整店名一眼能大致判业态，就接受相容原类或合理宽类；店名与地址能判归属就直接归挂，不搜索。

只有无法判断大致业态时才搜，每个未知对象只搜索一次，本批多个未知对象可集中检索；结果大致相容或可用合理宽类就接受，不继续追细。名称、身份、位置和归属疑点先看现有资料；公共信息不足、无法辨认公众用途的按总规则第4节直接排除，其它冲突待判，不为保住可疑点单独调查。共同片区依据的缺口交回区负责人集中处理。

公共信息不足且公众用途不明时，直接按非公共开放设施逻辑排除，留原ID、原行和短理由，不先标黄、不等中央退回重判，也不补查开放性。其它身份、位置冲突按总规则标黄／红止查；附近已有疑似同对象，优先标红、倾向弃置，无须为标记另搜或证明同体。

黄／红对象写辅助处置表及 open 问题，保存原因后继续下一项。没查到不证明不存在，但足以按写作尺度停止投入并提出弃置意见。低分、缺字段不单独触发自动排除。

修正坐标要保留原位置、采用位置、原因和证据，不能移到车站或行政中心占位；写作小片的就近归挂不改源点坐标。

## 层级与筛选

普通有效对象不选代表；可疑冗余按写作尺度标记。保留子集只填直接父，上层全部子集由程序沿成员图汇总。

| 实际结构 | 处理方式 |
|---|---|
| 生态街区→较小片区→商业街／设施／地点 | 小片框架建立后按大体位置和写作关联就近收纳，不要求逐点精确片区归属。 |
| 街区→商场→店铺 | 店铺挂商场，商场挂街区。 |
| 街区→具体街道→地点 | 地点挂真实具体街道。 |
| 商业街→综合设施→店铺→内部小设施 | 只记录实际存在且符合保留资格的层级。 |
| 商业街／设施本体与其周边 | 复用已有内部链，外围点就近吸纳进周边小片。 |
| 机场、景点、园区 | 按真实内部区域和设施逐层归挂。 |
| 仍有未解决对象或冲突 | 记具体待判和下一动作；不能只因精确边界未证实搁置可就近组织的点。 |

生态街区不自动等同行政町丁目或具体商业街。父类型由实际结构判断，不从分类 ID 硬推。

源对象实际担任父对象才需父类型；普通叶子不增加此义务。同一源主体不另造同体父。

商业街、设施和店铺内部链继续复用；外围点进入就近小片，写作小片组织与精确物理容纳分别说明，不把车站周边记成站内。不为外围吸纳重查已有内部链，详见总规则第 6 节。

先按公众用途和点位粒度筛选，再归挂。公共设施纯编号门、出入口、跑道及纯通行／运行点继续排除留痕。

休息室、店铺等合格独立用途保留。按本体判断，不关键词硬删，不把旅客正常准入当员工内部。

## 名称与后期任务

全区记录原名、异名、片假名、异体字、不同写法和来源已有拉丁拼写。

记录来源字段及品牌泛名、具体分支、主体别名和时期角色。

工程识别名须能辨认具体分店、分寺：已有完整名优先，否则有依据时写“品牌＋○○分店”“寺名＋○○分寺”或具体寺名。不只写品牌或裸地名，也不为补名穷找。

工程名写 name，派生名的角色和依据写辅助 fields；原始名只读，不自动翻译或设置已采用／激活状态。字段用法见字段参考第 7 节。

正文、一句话、搜索优化和后期公共项目下潜另期处理。需要后期处理的明确对象可关联任务 ID，不提前写正文。

## 保存与回货

每批保存主档及辅助记录；只更新必要任务结果，不另写大报告。

使用 `district_archive.py build` 派生、`check` 检查。不要手改生成十表。

回货说明任务 ID、领取版本、实际处理对象、待判和跨区事项。分母未知就如实标明，不以 0 冒充完成。

源对象分拣覆盖与片区框架任务分别收尾：负责人核对跨批新线索已怎样合并、实际归挂到哪一步、仍直接平铺的点是否还能收纳，以及具体剩余范围问题。带明确待判可以交候选，不以源覆盖完整代替片区工作结论，也不以一句话空位为缺口。

中央自动统一收货，返修只闭合点名问题，不重做已通过部分。自动接收仅形成候选，最终由用户与中央 6astra 共同判断后启用。
